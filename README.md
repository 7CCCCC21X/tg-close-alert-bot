# TG 合约昨收偏离提醒机器人

监控截图里的四个币安合约：**UNITREEUSDT、HK0625USDT、CXMTUSDT、SKHYNIXUSDT**。

最新成交价相对参考收盘价**上涨超过 1%，或者下跌超过 1%**，向 Telegram 私聊或指定群组话题推送提醒。代码存放 GitHub，Railway 常驻运行。仅监控，不会自动交易、下单或撤单，也不需要交易所 API Key、钱包或私钥。

## 先确认“上一日收盘价”的口径

**本版本默认自动获取币安合约上一完整 UTC 日的日 K 收盘价，不是股票交易所的正式昨收。**

- 当前价：币安合约最新成交价，不是标记价或指数价。
- 自动参考价：币安 `/fapi/v1/klines` 返回的上一完整 UTC 日日 K 的 `Close`。
- UTC 00:00 相当于北京时间 08:00，因此自动基准在北京时间每天 08:00 切换。
- 不是币安首页的滚动 24 小时涨跌幅，也不是北京时间昨天 00:00～24:00 的日线。
- 周末仍按合约自然日取日 K，不把周末当成股票交易日。
- **未自动接入上交所、港交所、韩国交易所的股票官方昨收，也未自动换汇。**

例如，北京时间 2026-09-18 15:00，日 K 模式取的是 UTC 2026-09-17 的完整日 K，结束于北京时间 2026-09-18 07:59:59.999；它不是 9 月 17 日下午股票交易所收盘时的股票价格。

若用途是 Predict 的股票“今日收盘比上个交易日收盘涨/跌”盘，不能直接把本机器人的默认基准当成该盘的结算基准。合约价格、股票原币种报价、汇率和市场指定结算数据源，必须分别核对。

程序另外提供**手动同口径参考价**模式。它只用你提供的价格做比较，不声称该价格已经核验为股票官方昨收，不自动进行币种、汇率或合约倍率换算。

## 默认提醒行为

计算公式：

```text
涨跌百分比 = (当前成交价 - 参考收盘价) / 参考收盘价 × 100
触发条件 = abs(涨跌百分比) > 1
```

假设参考价为 100：101.01 或 98.99 会触发；101、99、100 不触发。这里是严格“大于 1%”，不是“大于等于 1%”。

| 项目 | 默认行为 |
| --- | --- |
| 检查间隔 | 5 秒；采样不等 Telegram：消息在后台排队发送，采样照常进行 |
| 发送前复核 | 消息排队（例如 Telegram 429 冷却）期间行情变旧、超过 `MAX_PRICE_AGE_SECONDS`，或最新一次采样已不再触发，这条提醒直接作废、不补发旧价；下一轮用新行情重新判断。只有 Telegram 确认收到才记为已发送 |
| 首次采样已超过阈值 | 提醒，无需等下次穿越 |
| 持续超过阈值 | 每 300 秒再次提醒 |
| 偏离继续扩大 | 从超过 1% 到 2%、3% 等更高档位时再次提醒 |
| 同一合约最短通知间隔 | 30 秒，避免价格来回震荡刷屏 |
| 重新触发 | 回到阈值的 80% 内后重新武装；默认为 ±0.8% 内 |
| 涨跌反转 | 反方向超过 1% 时提醒，仍遵守 30 秒最短间隔 |
| 基准换日 | 日 K 模式：自动重新计算，新日 K 不可用时不沿用旧基准；交易所收盘时刻模式：保持到下一次已确认的交易日收盘替换，长假不过期 |
| 参考数据 | 交易所收盘、汇率、恒指、KOSPI、上证/A50、Hyperliquid、概率输入各自在后台独立刷新；5 秒提醒循环只读最近一次有效结果，外部接口变慢或挂起不会拖慢提醒 |
| 最新成交价过期 | 超过 120 秒未更新，暂停该项涨跌提醒并报告异常 |
| 网络故障/合约缺失 | 不生成假价格、不换成别的合约、不把数据缺失当作未触发 |
| 错误提醒去重 | 同一订阅同一数据项持续异常，最多每 30 分钟提示一次 |
| 状态持久化 | SQLite 保存订阅、话题、设置和已发送提醒，需要挂载 Volume |

5 秒轮询不能保证捕获两次采样之间瞬间发生又恢复的价格波动。这不是实时交易执行系统。HTTP 超时导致发送结果不确定，或者 Telegram 已接收后进程恰好在保存状态之前退出，仍可能出现偶发重复；不承诺分布式“恰好一次”投递。

## GitHub + Railway 部署

### 1. 创建专用 Telegram 机器人

在 Telegram 找到官方 **@BotFather**，发送 `/newbot`，按提示创建机器人并取得 Token。请给本项目使用独立机器人，不要和现有服务共用同一个 Token。

Token 只填在 Railway 的 **Variables**，不要提交到 GitHub，也不要发给别人。

### 2. 上传 GitHub

解压代码包。在 GitHub 新建一个私有仓库，例如 `tg-close-alert-bot`。

通过 **Add file → Upload files** 把解压后的文件和 `tests` 文件夹上传到仓库根目录。不要只上传 ZIP，也不要额外套一层目录。根目录应能直接看到 `main.py`、`Dockerfile`、`railway.json`。

```text
tg-close-alert-bot/
├── main.py
├── Dockerfile
├── railway.json
├── requirements.txt
├── .gitignore
├── .dockerignore
├── .env.example
├── railway-variables.example.txt
├── README.md
├── TESTING.md
└── tests/
    ├── run_all.py
    ├── offline.py
    └── test_*.py（26 组离线测试）
```

`Dockerfile` 会在构建时运行 `tests/` 里的全部离线测试（不联网、不需要 Token），任何一组失败都会让构建失败，不会上线有问题的版本。不需要在电脑上安装 Python，也不需要额外搭建数据库服务。

### 3. Railway 连接仓库

在 Railway 创建项目，选择 **Deploy from GitHub repo**，授权并选择刚才的仓库。先添加变量，再正式部署；若平台已经自动开始构建，补好变量后重新部署即可。

使用代码包中的 `Dockerfile` 和 `railway.json`，启动命令已配置为：

```text
python -u main.py
```

这是常驻 worker：**不要设置 /health 健康检查、不要配置 Cron。** 只有想用概率网页（`/web`）时才需要生成域名，见下文“概率网页”。

在服务设置中保持**单个部署区域、1 个副本**；关闭服务休眠/Serverless。不要同时在本地、预览环境和另一个 Railway 服务运行同一个 Token。运行环境应符合 Binance、Telegram、Railway 的地区及服务条款；不要通过非官方接口或关闭证书验证来绕过限制。

### 4. Variables 填写

在 **Variables → Raw Editor** 中粘贴下面内容。先只替换 Token；用户 ID 不知道时保留 0。

```env
TELEGRAM_BOT_TOKEN=替换成BotFather给你的Token
ADMIN_USER_ID=0
SYMBOLS=UNITREEUSDT,HK0625USDT,CXMTUSDT,SKHYNIXUSDT
ALERT_THRESHOLD_PCT=1
POLL_SECONDS=5
ALERT_COOLDOWN_SECONDS=300
ALERT_STEP_PCT=1
MIN_ALERT_GAP_SECONDS=30
MAX_PRICE_AGE_SECONDS=120
BASELINE_MODE=exchange_close
STATE_DB=/data/bot.sqlite3
EXCHANGE_TICKERS=UNITREEUSDT=sh:688836,HK0625USDT=hk:00625:same,CXMTUSDT=sh:688825,SKHYNIXUSDT=kr:000660
```

注意 `ALERT_THRESHOLD_PCT=1` 就是 **1%**，不是填 `0.01`。

`ADMIN_USER_ID` 是你本人的**数字用户 ID**，不是用户名、手机号、机器人 ID、群 ID 或话题 ID。没有设置管理员时，程序只允许查询 `/id`，不会让第一个陌生用户自动接管机器人。

`TELEGRAM_CHAT_ID` 不需要填写。程序不根据环境变量自动创建订阅；实际发到哪里，由管理员在那个私聊/群组话题里发送 `/subscribe` 决定。

### 5. 挂载持久磁盘

在 Railway 给**这个机器人服务**添加一个 **Volume**，挂载目录填写：

```text
/data
```

变量 `STATE_DB` 使用 `/data/bot.sqlite3`。不要把挂载路径写成文件名。

**一定要完成这一步。** 没有 Volume，容器重新部署后订阅、手动参考价、提醒去重记录和 TG 修改的设置可能丢失。磁盘本身不是自动创建的，`railway.json` 不能代替你添加 Volume。

### 6. 绑定管理员，开始订阅

先部署成功。在你的机器人私聊里发送：

```text
/id
```

机器人会回复你的用户 ID。把数字填回 Railway 的 `ADMIN_USER_ID`，保存并重新部署。

重新部署后，在机器人私聊发送：

```text
/subscribe
/status
```

你应当看到四个合约的当前成交价、基准价、相对基准涨跌和行情时间。**只有 `/status` 中各项数据有效，才说明行情链路也在工作。** 单独收到 `/test` 并不代表已订阅，也不代表行情接口正常。

### 7. 推送到群组话题

把机器人加入目标群，确认它可以发送消息。使用管理员本人账号进入目标话题，在**话题内部**发送：

```text
/subscribe@你的机器人用户名
```

程序同时保存 `chat_id` 和 `message_thread_id`，后续通知会发回该话题，不会只发到群组默认页面。

用同样方式可以在另一个话题订阅。各个订阅分别保存提醒状态。`/pause`、`/resume`、`/unsubscribe` 只作用于发命令的当前私聊/话题；`/threshold`、`/cooldown`、`/mode` 则修改所有订阅使用的全局设置。

## 按证券交易所收盘时刻取基准（/mode exchange）

日 K 模式的基准是币安合约在 UTC 0 点（北京 08:00）的价格，而“证券交易所收盘价”是股票当天收市时的价格，两者不是同一时点，所以“相对基准”和“相对交易所”会有差。发 `/mode exchange` 后，基准改为币安合约在标的交易所最近一次收盘时刻的价格：上交所 15:00、港交所 16:10、韩交所 15:30（当地时间），从币安该分钟的 1 分钟 K 线收盘价取；那一分钟没有成交时改用标记价 K 线，并在基准说明里标明“成交价”或“标记价”。

收盘时刻只取自动获取、**带交易日期**的交易所日 K（与“证券交易所收盘价”共用同一个时间戳），不再按工作日日历推算，避免把假期（例如 9 月 25 日中秋休市）当成交易日。当天的收盘要在收盘 15 分钟后才生效，之前沿用上一交易日。

基准会一直保持到下一次**已确认**的交易日收盘替换它，不会因为长假或周末过期（仅设 30 天安全上限，防止数据源坏掉几周后仍拿旧价报警）。例如 9 月 24 日收盘后遇到 9 月 25 日休市和周末，9 月 28 日开盘前、盘中都继续用 9 月 24 日收盘时刻的基准；9 月 28 日收盘 15 分钟后若日 K 还没更新，基准说明后面会加“⏳ 09-28 收盘待确认，沿用此基准”，日 K 一到就自动换成 9 月 28 日。行情源故障、只拿到不带日期的报价时同样沿用上一次基准；从没确认过收盘（例如首次部署时日 K 全部失败）的合约会暂停提醒并在状态里说明原因。基准保存在 SQLite，重启不丢。没有配置 `EXCHANGE_TICKERS` 的合约在此模式下不发提醒，并在状态里说明。配置了 `EXCHANGE_TICKERS`（默认已配置四个）时这就是默认模式；想回到 UTC 日 K 基准发 `/mode daily`，或设 `BASELINE_MODE=binance_daily`。

## 成交稀疏时的标记价

币安 `ticker/price` 的时间戳是最后一笔成交的时间。`HK0625USDT` 这类成交稀疏的合约在港股收盘后常常几分钟没有成交，会触发“最新成交价已过期”。程序同时读取币安 `premiumIndex` 的标记价（每秒更新）：最新成交价在 `MAX_PRICE_AGE_SECONDS` 内就用它；过期而标记价新鲜时改用标记价判断涨跌，状态和提醒里会写成“标记价 38.52｜基准 39.6（最新成交 38.49，185 秒无成交，改按标记价判断）”；两者都过期才暂停该合约的提醒。标记价接口失败只会退回到只看最新成交价。

## 手动参考价模式

它适合已经核对参考价格、需要让机器人围绕这条固定价格线提醒的场景。

以下为**虚构示例，不是实际昨收价**：

```text
/mode manual
/setclose 2026-09-18
UNITREE 75 09-17 16:00
SHEIN 40 09-17 16:00
CXMT 8 09-17 15:00
SKHYNIX 1300 09-17 14:30
/status
```

`/setclose` 可以一次发多条：每行（或用逗号分隔）一组「合约 价格 [收盘时间]」。收盘时间写 `MM-DD HH:MM` 或 `YYYY-MM-DD HH:MM`（北京时间），表示这条价格是什么时候收盘的；可以省略。它会显示在设置回复、`/status` 和涨跌提醒里，不影响判断逻辑。首行单独写一个 `YYYY-MM-DD` 日期表示统一适用日，也可以在首行写统一收盘时间；某一行自己写了则以自己的为准。全部行校验通过才写入，有一行写错则整批不生效。仍然支持单条 `/setclose UNITREE 75`。发 `/mode manual` 时机器人会回一份包含全部合约的模板，把“价格”和“MM-DD HH:MM”替换后发回即可。

日 K 模式下基准是币安上一个 UTC 日的日 K 收盘：标注为 2026-09-17（UTC 日）的 K 线在 2026-09-18 00:00 UTC 收盘，即北京时间 09-18 08:00，`/status` 里写作“收盘 09-18 08:00（北京时间，即 UTC 00:00）”。

## 证券交易所收盘价对照

币安日 K 昨收和股票交易所的正式收盘价并不相同。程序会自动获取每个合约标的股票的交易所收盘价（见下节），按汇率折成美元后显示“相对交易所”涨跌。也可以用 `/setexchange` 手动记录，语法和 `/setclose` 完全一样（可批量、可带收盘时间），当日的手动记录优先于自动值：

```text
/setexchange 2026-09-18
SHEIN 310.5 HKD 09-17 16:00
CXMT 58.2 CNY 09-17 15:00
SKHYNIX 258000 KRW 09-17 14:30
```

之后 `/status` 和每条涨跌提醒会在基准行之外显示，例如：

```text
├ 交易所 514.98 CNY ≈ 72.227（09-18 15:00 收·腾讯）→ 🔴 +5.79%｜当日 🔴 +0.36%
```

每一行的格式统一为“来源 价格（时间·数据源）→ 币安现价相对该行价格的偏差”，“当日”是股票自身从昨收到今收的涨跌。

港股 SHEIN 的 `HK0625USDT` 是 quanto 合约，合约价格数值就是港币股价，因此直接比较、不折算（`EXCHANGE_TICKERS` 里带 `:same`）。其余三个合约以美元计价，交易所收盘价先按汇率折成美元再比较。

“相对基准”和“相对交易所”参照的是两个不同时点的价格：基准是币安日 K 在北京 08:00 的收盘（股票开盘前），交易所收盘价是当天收市时的股价。为了让两者的差距能读懂，交易所那一段还会显示“股票当日：-4.574%（昨收 39.57）”，即股票自身从昨收到今收的涨跌；合约当前价相对交易所收盘价的差就是永续合约在股市收市后的溢价或贴水。价格行里的“币安指数”是币安自己计算的标的指数价，可用来核对程序抓到的交易所收盘价是否一致。

### 自动获取证券交易所收盘价

四个合约的标的股票都已上市，程序默认会自动拉取它们最近一个已完结交易日的收盘价，填到“证券交易所收盘价”一行，并标注来源和“自动”：

| 合约 | 标的 | 交易所代码 | 数据源 |
| --- | --- | --- | --- |
| `UNITREEUSDT` | 宇树科技 | 上交所科创板 688836（2026-08-19 上市） | 东方财富日 K 接口 `push2his.eastmoney.com/api/qt/stock/kline/get`，`secid=1.688836` |
| `HK0625USDT` | 希音 SHEIN | 港交所 00625（2026-09-01 上市） | 东方财富日 K 接口，`secid=116.00625` |
| `CXMTUSDT` | 长鑫科技 | 上交所科创板 688825（2026-07-27 上市） | 东方财富日 K 接口，`secid=1.688825` |
| `SKHYNIXUSDT` | SK 海力士 | 韩交所 000660 | Naver 金融日线接口 `fchart.stock.naver.com/sise.nhn?symbol=000660&timeframe=day` |

韩股的来源标签（2026-10 起按实际取值标注）：先取 Yahoo `000660.KS` 日线（只含 KRX 正规时段）；Naver 日线会混入 Nextrade 盘后成交，所以用 Naver 实时价（KRX 正规时段）核对。来源写“Naver KRX”表示用的是 KRX 正规时段的收盘；实时价读不到或没有报价时间时，Naver 日线的值原样保留并写“Naver 日K·含 NXT”，提醒它可能含盘后成交；Yahoo 的收盘只有在真的被另一个值替换时才改标，数值相同就仍写 Yahoo。

规则：每 10 分钟刷新一次，A 股/港股按“东方财富 → 腾讯（`qt.gtimg.cn`）→ 新浪（`hq.sinajs.cn`）”的顺序尝试，每个来源失败重试一次，来源名显示在“来源 上交所688836·腾讯”里；最近一次成功的值会保存到 SQLite，重新部署或接口暂时失败时沿用并标注“最近一次刷新失败”。取最近一个已完结交易日的日 K 收盘（当天的 K 线要到官方收盘价确定后 15 分钟才算完结）。各交易所官方收盘价的确定时间（2026-09 核对）：上交所/深交所 15:00（科创板 15:05–15:30 的盘后固定价格交易按该收盘价成交，不改变收盘价）；港交所 16:00–16:10 收市竞价，收市价在 16:08–16:10 确定，显示为 16:10；韩交所正规交易 09:00–15:30，官方收盘价在 15:30 确定，2026-09-14 起新增的 15:40–16:00 收盘价交易和 16:00–20:00 盘后连续交易不改变官方收盘价。非北京时区的交易所同时显示当地时间和北京时间，例如“收盘 09-18 14:30（北京时间，韩国 15:30）”；币种按交易所（CNY/HKD/KRW）标注，因此默认只展示不算涨跌。全部来源都失败且没有历史值时 `/status` 才显示“自动获取失败（各来源原因）”，其他合约不受影响；腾讯/新浪实时接口在盘中只能给出昨收而不知道确切日期，此时显示“上一交易日”且不带收盘时间；用 `/setexchange` 手动记录的当日价格优先于自动值。

映射由环境变量 `EXCHANGE_TICKERS` 控制，格式 `合约=市场:代码[:same]`，市场取 `sh`/`sz`/`hk`/`kr`；某个合约的报价单位与股票本币相同时加 `:same` 就会计算“相对交易所”涨跌；设为 `off` 关闭自动获取。`python main.py --check` 会连同币安数据一起打印四个交易所收盘价，可用来验证接口是否可达。

这些是第三方非官方公开接口，不是交易所官方数据源，可能限流或改版；程序只读、失败不影响涨跌提醒。

### 恒指期货（含夜市）

`/status` 顶部和港股标的（如 `HK0625USDT`）的涨跌提醒里会显示恒生指数期货主力合约的即时报价，包括 17:15–03:00 的夜市（T+1 时段），并与恒生指数现货比较给出高水/低水，例如：

```text
📈 恒指期货 夜市 24,706 → 恒指收盘 24,750.78 🟢 -0.18%（低水 45）｜恒指当日 🔴 +0.60%｜期货前收 24,736 🟢 -0.12%（-30）｜09-18 22:01 etnet
```

箭头后是期货价相对恒生指数的偏差：港股现货时段（09:30–16:10）对比实时恒指，收市后对比当天恒指收盘，括号里是高水/低水点数；“恒指当日”是恒指自身相对昨收的涨跌，“期货前收”是期货相对上一交易时段收市价。

数据源按“etnet 經濟通（`www.etnet.com.hk/www/tc/futures/index.php`，港交所指定的免费即时行情网站）→ 东方财富（`secid=134.HSI_M`）→ 新浪 `hf_HSI`”顺序尝试。etnet 页面同时给出日市、夜市和恒指现货。两段的时间只画在走势图图片里、正文没有，所以程序按价格判断哪一段更新：夜市的“前收市”等于日市最新价，说明这段夜市接在该日市之后（夜市更新）；夜市的“前收市”等于日市的“前收市”，说明那是日市之前的一段（日市更新）。非交易时段显示该段的收市时间并标“（已收市）”，例如周六显示“夜市（已收市）… 09-26 03:00”；周末和 `HOLIDAYS_HK` 假日不算交易时段。高水/低水直接采用 etnet 公布的数值。注意新浪 `hf_HSI` 是恒指 CFD，不是港交所合约（报价带小数、前收也不同），只在前两个来源都失败时兜底，行末会标“新浪CFD·非港交所合约，仅参考”；恒生指数现货按“东方财富 `100.HSI` → 腾讯 `hkHSI` → 新浪 `rt_hkHSI`”尝试（读各自的报价时间），现货取不到时只显示期货、不显示高低水；现货时段内 etnet 的现货不可信（停更、早于今日开盘、前收与上一交易日日 K 不符）时，也改问这三个带时间的来源。每 60 秒刷新一次，16:10 现货收市后立即多刷新一次以记下收市时的期货价；`HSI_FUTURES=off` 可关闭。港交所的 etnet 页面没有公开接口，这里用的是提供同一份港交所数据的第三方免费接口。

### KOSPI 综合指数

`/status` 顶部（恒指期货下面）和韩股标的（`SKHYNIXUSDT`）的涨跌提醒里显示 KOSPI 综合指数：点位、相对昨收的涨跌、开高低、更新时刻（北京时间）和交易状态，例如：

```text
🇰🇷 KOSPI 已收盘 3,371.89 → 昨收 3,359.55 🔴 +0.37%（+12.34）｜09-23 14:30 Naver
```

两行末尾都带数据的日期和时间；如果数据源给的还是前一天的数据（例如当天收盘后接口尚未更新），行末会标“⚠️ 非今日数据”。

箭头后是 KOSPI 相对昨收的涨跌。

KOSPI 综合指数（约 7,000 点）和 KOSPI 200（约 1,100 点，200 只大盘股）是两个不同的指数。Hyperliquid 上 trade.xyz 的 `xyz:KR200` 永续追踪的是 KOSPI 200，24 小时交易，可作为韩股收盘后的价格参考，因此程序再抓一条 KOSPI 200（Naver `index/KPI200`）并与 HL KR200 对比：

🇰🇷 KOSPI200 已收盘 1,105.3 → 昨收 1,095.5 🔴 +0.89%｜🌊 HL KR200 1,121.7 → 相对 KOSPI200 🔴 +1.48%（24h 🔴 +1.55%）｜09-23 15:15 Naver

HL 的指数市场由 `HL_INDEX` 控制（默认 `KR200=xyz:KR200`，`off` 关闭）。trade.xyz 目前的指数永续有 XYZ100、SP500、JP225、KR200，没有恒生指数，所以恒指仍只对比港交所的期货夜市。

数据源按“Naver 指数实时接口（`polling.finance.naver.com/api/realtime/domestic/index/KOSPI`）→ 东方财富（`100.KS11`）”尝试，Naver 报价停更或缺时间时自动改用东方财富，每 60 秒刷新；`KOSPI_INDEX=off` 关闭。韩交所正规交易 09:00–15:30 韩国时间，指数在收盘后不再变动；16:00–20:00 的盘后交易不计入指数。如需 KOSPI 200 夜间期货（18:00–次日 06:00）可以再加。

### Hyperliquid 参考价

每个合约下面还会显示 Hyperliquid 上同一标的永续合约的行情，作为币安之外的第二个参考：标记价、预言机价、24 小时涨跌、每小时资金费率，以及币安现价相对 Hyperliquid 标记价的偏差（港币计价的 quanto 合约会先按汇率折成美元再比）：

### 概率网页（/web）

机器人自带一个只读网页，显示和 `/prob` 相同的概率，每 10 秒自动刷新，手机上可以直接打开。页面分“指数”和“合约标的”两组，每张卡片只放公平价、涨/平/跌比例条、目标收盘、倒计时和“参考 → 有效（涨跌幅）”一行；代理、σ、z 收在可展开的“计算明细”里，展开状态在自动刷新时保留。每张卡片写明目标收盘（如“09-28 15:00 上交所收盘（北京时间）”），下方有逐秒跳动的“⏳ 距收盘”倒计时；倒计时以机器人的服务器时间为准，不受手机时钟误差影响，到点后显示“已到收盘时间，等待收盘价确认”。发 `/web`（已加入菜单）获取链接。

在 Railway 上开启：

1. 服务 **Settings → Networking → Generate Domain**。Railway 会自动注入 `PORT` 和 `RAILWAY_PUBLIC_DOMAIN`，程序据此监听端口并生成链接，不需要手动填变量。
2. 重新部署后发 `/web`，得到形如 `https://xxx.up.railway.app/p/<令牌>` 的链接。

说明：

- 链接里的令牌第一次启动时随机生成并保存在 SQLite，重新部署不变；想换就设置 `WEB_TOKEN`（16～64 位字母数字）。没有令牌的路径一律返回 404，令牌按常量时间比较。
- 网页只读，不能修改任何设置，也不展示订阅或 Telegram 信息；响应带 `no-store`、`noindex`、`no-referrer` 和限制性的 CSP。
- 其他部署环境用 `WEB_PORT` 指定端口、`WEB_BASE_URL` 指定公网地址；`WEB=off` 关闭。
- `/health` 返回 `ok`，可以作为健康检查路径。

### Predict 订单簿对比（/book）

机器人每 15 秒读取 Predict.fun 上对应的每日涨跌市场订单簿（只读，不下单），和模型公平价比较，告诉你挂哪边优势大。`/book` 列出全部标的并附市场链接，`/prob` 和概率网页的每张卡片也附带盘口。网页上盘口那行开头的“Predict ↗”按钮在新标签页打开对应的 Predict 市场（链接带邀请码 `?ref=B00EA`）；四个优势格子点了不跳转，而是展开明细（见下）。

市场链接按目标收盘日自动拼出，日期变了不用改任何配置：

```text
https://predict.fun/zh-cn/market/hang-seng-index-up-or-down-on-september-28-2026
                                 └── 前缀 ──────┘            └ 月-日-年（目标收盘日）┘
```

目标日和概率模型一致（盘中是今天收盘，收盘后是下一个交易日），所以盘口和概率对的是同一个市场。默认前缀：

| 标的 | 前缀 |
| --- | --- |
| 恒生指数 `HSI` | `hang-seng-index` |
| KOSPI `KOSPI` | `kospi-composite-index` |
| 上证指数 `SSE` | `sse-composite-index` |
| 宇树 `UNITREEUSDT` | `unitree` |
| 希音 `HK0625USDT` | `shein` |
| 长鑫 `CXMTUSDT` | `cxmt` |
| SK 海力士 `SKHYNIXUSDT` | `sk-hynix-inc` |

订单簿报价的是“涨”：买 1 份跌 @ p 等于卖 1 份涨 @ 1−p。对每个方向算 **净优势**（每份，¢）：

| 方向 | 价格 | 净优势 |
| --- | --- | --- |
| 挂涨（在买1排队） | 买1 | 公平涨 − 买1（挂单免手续费） |
| 挂跌（在卖1对面排队） | 1 − 卖1 | 公平跌 − (1 − 卖1) |
| 吃涨（立即成交） | 卖1 | 公平涨 − 按单笔金额吃过卖盘的均价 − 手续费 |
| 吃跌（立即成交） | 1 − 买1 | 公平跌 − 按单笔金额吃过买盘的均价（换算成跌） − 手续费 |

- **手续费**：吃单每份 = 费率 × min(价格, 1 − 价格)（Predict 基础费率 2%，50¢ 时最高 1¢，越接近 0/100 越低）；费率优先取该市场自己公布的 `feeRateBps`，取不到时用 `PREDICT_FEE_BPS`。挂单不收手续费。
- **深度/滑点**：吃单按 `PREDICT_TRADE_USD`（默认 $100）一档一档吃下去算均价；前 5 档不够吃完时写明“盘口只够 N 份”。
- **门槛**：建议的方向必须超过 max(`PREDICT_MIN_EDGE_CENTS`（默认 2¢）, 模型误差)。模型误差 = 把 σ 乘或除以 1.25、代理映射的估算再把代理系数 β ±0.25 时，公平价最多变动多少；落在这个范围内的优势不算数。

例：截图里恒指买1 81¢、卖1 85¢，盘后按期货估算的公平涨 78¢：挂跌 15¢ 净 +7.0¢；吃跌毛优势 +3¢，但按 $100 吃过 81/80/79¢ 三档后均价 19.25¢、再扣 0.4¢ 手续费只剩 +2.4¢，低于这次的门槛 6.1¢（期货映射的 β 不确定性让公平价可上下浮动约 6¢），不建议吃单：

```text
📍 恒生指数
├ 📕 Predict 涨 买1 81.0¢×400｜卖1 85.0¢×12｜中间 83.0¢
├ 模型 涨 78.0¢｜跌 22.0¢｜净优势门槛 6.1¢（模型误差 6.1¢）
├ 挂涨 81.0¢ 净 -3.0¢｜挂跌 15.0¢ 净 +7.0¢（免手续费）
├ 吃涨 85.0¢ 净 -15.1¢｜吃跌 19.0¢ 净 +2.4¢（按 $100 吃单：含深度与手续费）
├ 👉 挂单 挂跌 @ 15.0¢ 净优势 +7.0¢（排队，成交不保证）
└ https://predict.fun/zh-cn/market/hang-seng-index-up-or-down-on-september-28-2026?ref=B00EA
```

网页上每个格子显示净优势。卡片上不写门槛数字，只看颜色：加框的是建议方向（净优势 ≥ 高亮门槛时是红框），深色的也超过了建议门槛但不是最优，灰色的优势不够大、不建议。**点一下格子**（手机、电脑都行）在下面展开这一格的明细，再点一下收起，10 秒自动刷新时保持展开：

```text
挂跌 @ 15.0¢：挂单排队，成交不保证，免手续费
模型公平价 39.9¢ − 15.0¢ = 毛优势 +24.9¢
这个价位已有 12 份在排队
净优势 +24.9¢ · 建议门槛 2.4¢（模型误差） → 满足
高亮门槛 10¢ → 标红框
```

吃单格子写的是“按 $100 吃单：均价 93.0¢（深度滑点 +8.0¢）· 手续费 0.1¢/份 · 约 108 份”；已读取的盘口不够吃完时格子上标“深度不足”，明细写“盘口只够买 N 份”。“建议门槛”是模型给建议所需的最低净优势（max(最低净优势, 模型误差)），过不了就不建议；“高亮门槛”只决定要不要标红框（默认 10¢，可在 ✎ 自定义里改），两者不是一回事。市值阶梯、价格阶梯点某一档的那一行，先是这一档的一行说明（还要涨跌多少才碰到、模型价、盘口，以及 ⚠️ 的原因或暂不建议的原因——手机上没有悬停，这些只能这样看到），再是这一档的四个方向格子，同样可以再点开明细。筛选条下面有一行“🔥 机会 N”，列出页面上所有标红框的建议（按净优势从大到小，最多 8 个），点一个就跳到那张卡并闪一下边框；✎ 自定义时和数据过期时不显示。✎ 自定义里可以选机会条列出哪些栏目，或者只列吃单（挂单的优势要等成交才算数）。Telegram 的 /book、/prob 仍写出门槛。

说明：

- 挂单优势包含了价差，但要排队、不保证成交；吃单立即成交。挂单和吃单分开评估，各给一个“👉”建议；都不超过门槛时显示“暂不挂”。
- 未计积分、LP 奖励和挂单返佣；模型本身有误差（见 `/calib`），优势只是参考。

- Predict 上还没上架的市场显示“Predict 上还没有这个市场（slug）”，1 分钟后再查（新上架的市场最多延迟约 1 分钟出现）；网络失败会显示原因并保留上次盘口。
- 订单簿走 `https://api.predict.fun/v1/markets/<id>/orderbook`。如果 `/book` 显示 HTTP 401/403，到 Predict.fun 申请 API key 填进 `PREDICT_API_KEY`（建议单独一个 key，别和交易程序共用限流桶）。

### 优势提醒（Telegram）

价格阶梯的挂单提醒单独跟踪，只针对积分已激活且报价符合上述条件的档位，沿用下面的优势门槛、持续确认和冷却时间；吃单提醒照常运行。积分未激活或状态无法确认时停止新的挂单机会提醒，撤销未发送的旧挂单机会；已提醒的建议失效后提示检查撤单。这个积分限制只适用于价格阶梯，其他栏目的挂单提醒保持原有逻辑。提醒中的优势仅为模型公平价减报价，不把积分计作收益，也不保证该挂单成交或实际获得积分。

不用一直盯着网页：机器人给已订阅的聊天（和涨跌提醒同一批）发三种消息，覆盖所有带 Predict 盘口的卡片（指数、个股日涨跌、先触价、BTC 月度涨跌、HYPE 反超 SOL、价格阶梯和市值阶梯的每一档），判断方式和网页上的建议完全一样：

- 🟢 **新机会**：卡片的建议方向净优势达到 `EDGE_ALERT_CENTS`（默认 10¢），并持续 `EDGE_ALERT_CONFIRM_SECONDS`（默认 60 秒）。写明方向、价格、净优势、模型公平价，是挂单还是吃单（吃单按 `PREDICT_TRADE_USD` 计，已扣手续费和深度），同时够大的其他方向，以及市场链接。
- ⚪ **建议失效**：提醒过的那一边（例如 No）已经没有任何方向超过建议门槛，并持续 60 秒。只是从 10¢ 掉到 10¢ 以下、仍在建议范围内时不发，避免在 10¢ 上下来回提醒。
- 🔄 **方向反转**：提醒过的那一边不再建议，另一边成了建议方向，并持续 60 秒。另一边也有 10¢ 以上时，它算作已提醒，之后它失效还会再提醒。
- 后两种都带一句“⚠️ 如果按之前的提醒挂了单，请检查是否撤单或改价”。
- 同一个市场同一边提醒过“新机会”后，`EDGE_ALERT_COOLDOWN_SECONDS`（默认 900 秒）内不再当作新机会提醒。
- 盘口过期（超过 90 秒没刷新）或卡片暂不建议（行情过期、锚点是近似值、σ 是先验值等）时不做判断、不发提醒，数据恢复后重新计时。市场结束（卡片换到下一天的市场）后不再提醒。
- 每个订阅发送成功才登记；发送失败的在 10 分钟内每轮重试，期间这个市场有了更新的变化就只发最新那条。状态存 SQLite（`edgealerts`），重启后接着判断。

```text

挂跌 @ 52.0¢｜净优势 +20.0¢（模型 72.0¢）
挂单：排队等成交，不保证成交
也可以：吃跌 @ 55.0¢ +16.1¢
https://predict.fun/zh-cn/market/hang-seng-index-up-or-down-on-october-5-2026?ref=B00EA

⚪ 建议失效｜恒生指数（10-05）
之前提醒：挂跌 @ 52.0¢ +20.0¢（10:04）
现在这一边最好是 挂跌 +1.5¢，不到建议门槛 2.0¢，不再建议
⚠️ 如果按之前的提醒挂了单，请检查是否撤单或改价
https://predict.fun/zh-cn/market/hang-seng-index-up-or-down-on-october-5-2026?ref=B00EA
```

| 变量 | 默认 | 说明 |

| `EDGE_ALERT_CENTS` | `10` | 提醒“新机会”所需的净优势（¢/份），1～50 |

### 模拟交易（/sim）

回答“净优势有 10 个点就买 100 份，长期下来是赢还是亏”。机器人只记账，**不会向 Predict 下任何单**。

- **何时买**：默认只做指数和个股日涨跌的卡片、只吃单（`SIM_MARKETS=close`、`SIM_WAYS=taker`）：这类卡给出建议、且吃单方向的净优势 ≥ `SIM_EDGE_CENTS`（默认 10¢）时，买 `SIM_SHARES`（默认 100）份。`SIM_MARKETS` 可以填 `all` 或 `close,touch,updown,flip,range,ladder` 的组合（先触价、BTC 月度涨跌、HYPE 反超 SOL、价格阶梯、市值阶梯的每一档），`SIM_WAYS` 可以是 `taker`、`maker` 或 `both`；缩小范围后，已经开着的仓位照常成交和结算，只是不再新开。价格阶梯无论怎么设都只吃单。挂单和吃单像页面上的建议一样分开判断，同一个市场、同一边、同一种方式只买一次，优势持续多久都不加仓。卡片暂不建议的情况（行情过期、锚点是近似值、σ 是先验值、盘口方向未确认、盘口过期等）一律不买。
- **吃单**：按 `SIM_SHARES` 份本身判断和成交：沿盘口吃这么多份的均价加手续费就是成本，净优势 = 公平价 − 成本，这个数达到门槛才买（信号、成本、净优势是同一个数；卡片上按 `PREDICT_TRADE_USD` 算的优势另外存着对照）。只看最优价够、按份数吃下去不够的，不买。盘口不够吃完时只算吃到的份数，并标“盘口不够”。
- **挂单（推定成交）**：按建议价挂着，假设排在下单时该价位已有挂单的后面。之后只有盘口出现**卖到挂价或更低的卖单**时才算成交（这时该价位原有的买单已经没了，排在前面的也就没了），**按看到的数量**算，最多到下单份数；同一张卖单每次刷新都会再看到，所以只取看到的最多一次，不累加。可能部分成交；市场出结果时没成交的部分作废，只有成交的份数算盈亏。这些都标“推定成交”，和吃单的立即成交分开看。
- **两个模型预期**：下单时的预期 = 下单时净优势 × 成交份数；成交时的预期 = 每份成交那一刻的公平价 − 成本。挂单常在行情转向时才被成交，成交时预期会明显低于下单时，两者都显示。
- **结算**：先用机器人的数据**预结算**，再以 **Predict 的结果确认**：
  - 预结算：指数日涨跌按官方收盘（收盘后 1 小时，和 /calib 同一份收盘记录，并记下这个收盘来自哪个源），个股按交易所收盘，和下单时卡片用的参考线（Predict 目标价或昨收）比：高于为涨，低于为跌，相同各算一半。先触价要把**整个窗口核验到截止那一分钟**（截止所在的那一小时逐分钟读）才按“都没碰到 50/50”结算；BTC 月度涨跌按币安两根 1 分钟 K；HYPE 反超 SOL 按 Hyperliquid 1 分钟 K（窗口核验完仍未反超为 No）；价格阶梯按币安小时 K 读出的本月最高/最低（碰到即 Yes，整个窗口读完仍没碰到为 No）；市值阶梯按**窗口内**的最高（截止后读到的价格不算），历史没读全（没有 K 线源、开窗那一小时缺分钟 K、没读到截止）时不预结算。本地数据后来更正（例如实时报价换成日 K 收盘）会重新结算并留下修订。
  - Predict 确认：市场到期后，每个市场最多 10 分钟问一次 Predict 的结算结果。和预结算一致 → “已确认”；不一致 → 按 Predict 的结果重新结算，标“**结果不一致**”，原来的结果和修订都保留；本地数据定不了的，直接按 Predict 结算。读不到或还没结算时保持“预结算 / 待确认”。
- **每笔的证据**（下单时和每次成交时都存）：判断依据（模型公平价、参考价、有效价、σ、β、距收盘时间）、行情来源（真实来源、代码、报价时间、抓取时间、价格类型）、代理与锚点（代理合约、合约月份、锚点价格和时间、是否近似）、成交证据（盘口快照、成交份数、均价、手续费、滑点、看到的卖单和排队变化）、结算证据（规则、本地结果和来源、Predict 结果、确认时间、修订记录）、版本（代码版本、模型参数、策略设置）。旧版本记下的交易没有这些快照，复盘页会注明。
- **看结果**：`/sim` 和网页的“模拟交易”栏显示已结算笔数、胜负、成本、回款、盈亏、两个模型预期、已确认 / 预结算 / 结果不一致的笔数，按市场类型和挂单 / 吃单分开统计，并列出最近的交易。主页的“模拟交易”栏**默认隐藏**，在 ✎ 自定义里勾上“模拟交易”就会出现。
- **复盘页**（`/web` 链接后加 `/journal`，`/sim` 和 ✎ 自定义里都有链接）：每笔一行，可按状态（持仓/挂单、预结算、已确认、结果不一致、未成交）、挂单/吃单和市场类型筛选；点开一笔看上面六组证据。每笔的链接（`/journal#编号`）可以直接打开这一笔。
- **导出日记**：复盘页的“导出 CSV”（一笔一行，含参考线、有效价、σ、β、口径、下单距收盘、最旧报价年龄、行情来源、代理与锚点、本地/Predict 结果、修订等，带 BOM，Excel/WPS 直接打开）和“导出 JSON”（每笔的完整记录）。
- 只从部署这版开始往后记，没有历史盘口可以回测；记录存在 SQLite（`sim:` 开头，收盘来源在 `outsrc:` 开头），重启不丢。

| --- | --- | --- |
| `SIM` | `on` | `off` 关闭模拟交易（`PREDICT=off` 时也不运行） |
| `SIM_EDGE_CENTS` | `10` | 触发买入的净优势（¢/份），0.5～50 |
| `SIM_SHARES` | `100` | 每次买多少份 |
| `SIM_WAYS` | `taker` | 模拟交易做哪种单：`taker` 只吃单、`maker` 只挂单、`both` 都做 |
| `SIM_MARKETS` | `close` | 模拟交易做哪些市场：`all`，或 `close`（指数/个股日涨跌）、`touch`、`updown`、`flip`、`range`、`ladder` 的组合 |

### 上证指数与 A50 夜盘

`/status` 顶部、KOSPI 下方显示上证指数、富时中国 A50 期货和上证的收盘概率；宇树、长鑫等沪市标的的提醒里也带上证行：

```text
🇨🇳 上证 已收盘 3,850.12 → 昨收 3,830 🔴 +0.53%（+20.12）｜09-30 15:00 腾讯｜收盘 09-30 3,850.12（腾讯日K确认）
📈 A50期货 夜盘 14,020 → 上证收盘时 14,160 🟢 -0.99%｜昨结 14,100 🟢 -0.57%｜09-30 22:01 东方财富
🎲 上证 10-08收 涨 34.0¢｜跌 66.0¢（有效 3,819.64·σ 1.92%）
```

- **上证指数**：实时行情腾讯 `sh000001` → 新浪 → 东方财富 `1.000001`，每个源都校验返回的确实是上证指数（代码 000001、沪市），不是就换下一个源。
- **盘后收盘价**：只用**带交易日期**的上证日 K（腾讯 `fqkline` → 东方财富 `secid=1.000001`，同样校验代码）确认，不用实时行情的“最新价”——实时源在假期或故障时可能停在旧报价。当天的 K 线要到 15:15 才算完结。按交易日历（含 `HOLIDAYS_CN`）应已收盘、但日 K 还没出来时，上证行显示“**收盘价待确认**”，概率显示“收盘价待确认（等待 09-28 上证日 K，日 K 最新为 09-24）”，不输出概率。例如 9 月 24 日收 3888.37 点、25–27 日休市，9 月 28 日开盘前的参考收盘仍是带“09-24”日期的 3888.37，而不是自然日“昨天”的数据。
- **报价时效**：盘中上证实时报价超过 10 分钟没更新（午休 11:30–13:00 不计）、或 A50 在交易时段内超过 10 分钟没更新时，暂不输出新概率；上证开盘期间实时报价失效时直接暂停，不会悄悄改用 A50 映射。A50 休市时还会检查报价是否接近最近一次交易时段结束；例如周六读到周五中午的旧价会停算，周六 05:15 收市附近的报价可以继续作为休市参考。多个来源时，排在前面的源返回旧报价或没有行情时间，不再算“取到了”，而是继续问下一个源，都不新鲜时保留最新的一笔并写明原因（见下文“行情时效”）。
- **A50 期货**（新加坡交易所，日盘 09:00–16:30、夜盘 16:45–次日 05:15）：东方财富 `104.CN00Y`（当月连续）→ 同一合约的东方财富 1 分钟 K 线最新一根（另一台服务器，仍是同一期货，可与东方财富锚点对算）→ 新浪 `hf_CHA50CFD`（标注“非交易所合约”）。前面的源失败而由后面的源顶上时，A50 行会写“⚠️ 前序源未取到：东方财富: …”，方便看出东方财富为什么没取到。代码校验只要求是 A50 合约（`CN` 开头，如 CN00Y、CN2610），不会因为连续/具体月份写法不同而误拒。锚点必须和当前实时价来自同一条行情：实时价用东方财富时，锚点取东方财富 1 分钟 K，缺失时退到 5 分钟 K；实时价用新浪时，锚点取新浪同一合约（`hf_CHA50CFD`）的 5 分钟 K。两边都取不到时，用程序在当天 15:00–15:05 实时记下的第一口价（每个交易日自动记录并保存，因为收盘价要 15 分钟后才由日 K 确认）。两者来源不同就不混算，概率处写明原因。注：2026-09 在 Railway 上实测，东方财富所有接口都连不上（502/断开/超时），A50 只能依赖新浪。注意当月连续在到期日前后会换月。
- **锚点**：优先取东方财富 A50 连续合约在上证收盘日 15:00 的 1 分钟 K；如果历史 1 分钟线已滚出窗口，再按相同日期和代码取标为 15:00 的 5 分钟 K 收盘价，并明确标注“五分钟K近似”。两种历史线都没有时，仅在收盘后 5 分钟内用第一口实时报价作近似。日期、价格、精度与来源一并存入 SQLite，重启后恢复；后续若取得 1 分钟线会升级锚点。连续合约与新浪 CFD 来源不同时暂停代理概率，不混算两种价格。
- **没有历史锚点时**：无法取得该收盘日的 1 分钟或 5 分钟 K，就显示缺少哪天的锚点并暂停概率；不把 A50 行情的“昨结”或当天现价冒充上证 15:00 时刻的 A50。上证 15:00–15:15 等待带日期的日 K 确认，期间不输出下一次收盘概率。
- **有效价** = 上证收盘 × exp(β × ln(A50 现价 / A50 锚点))，β 默认 0.8（`A50_BETA` 可改）：A50 只有 50 只大盘股，上证的涨跌幅通常比 A50 小。
- **σ**：确认收盘时读到的 40 根上证日 K，与 1.1% 的先验合成。
- **回测数据**：上证、KOSPI、恒指的概率每 30 分钟存一条快照，存的就是网页和 `/prob` 当时显示的概率：按 Predict 目标价重算过的，就存重算后的概率和目标价，同时保留模型原始参考收盘和原始概率、Predict 市场 slug 和链接、代理涨幅、β、σ、剩余方差、盘中/盘后；官方收盘确认后另存结果。打分（Brier、校准）按显示的概率和它所用的参考线判涨跌，代理系数拟合仍用模型原始参考收盘。`/calib` 按指数和盘中/盘后分别给出 Brier、对数损失、校准表，并拟合“ln(收盘/参考) = 截距 + 系数 × 代理涨幅 + 残差”；每个目标日权重相同，自由度按日数算。逐日向前检验只用已收盘的日子预测下一日，至少 15 个目标日才下结论。β 和 σ 仍需人工根据报告修改。
- 上证目前没有单独的 ±1% Telegram 涨跌提醒：它只作为参考行和概率出现在 `/status`、`/prob`、网页和沪市标的的提醒里。
- 上证盘中（09:30–15:00）直接用现货相对昨收；`SSE_INDEX=off` 关闭。

### 交易所假期

目标日跳过周末和预设的交易所假期，跨越的每个工作日假期按半天方差计入 σ（假期里消息照常发生）。预设：A 股 2026-09-25 与 10-01～10-07（上交所公告），韩交所 2026-09-24、09-25、10-05、10-09，港交所 2026-10-01。可用 `HOLIDAYS_CN`、`HOLIDAYS_KR`、`HOLIDAYS_HK` 覆盖，格式 `2026-10-01..2026-10-07,2026-12-31`。

### 收盘涨跌概率（/prob）

每个合约块、恒指和 KOSPI 下面各有一行 🎲，给出“下一个交易所收盘价高于/低于参考收盘价”的模型概率，按预测市场的公平价写成 ¢：

```text
🎲 KOSPI 09-28收 涨 28.2¢｜跌 71.8¢（有效 6,958.67·σ 3.02%）
```

涨跌提醒里也带同一行 🎲（位于触发原因之前），每条提醒都附带当时的收盘概率。发 `/prob`（已加入菜单）查看每一项的计算过程：参考收盘、代理、有效价、σ、z 和严格涨/平/跌三个概率。算法：

1. **有效价** = 参考收盘 × 代理现价 ÷ 代理在参考收盘那一刻的价格。合约用币安合约（取收盘那一分钟的 K 线）；KOSPI 休市时用 HL `xyz:KR200`（锚点取 KOSPI 15:30 收盘那一刻的 HL 1 分钟 K；HL 只保留约 3.5 天分钟线，取不到时退用同一时刻的 5 分钟 K，再退用 15:30 后两分钟内实时记下的标记价；锚点持久化，假期中重启不丢。锚点是成交 K 线收盘价，所以现价取 HL 盘口中间价（没有时才用标记价），两边同口径；有效价 = KOSPI 收盘 × exp(β × ln(现价/锚点))，β 默认 1（`KOSPI_BETA`）。KOSPI 基准停在比应有收盘日更早的日期时也暂停。不再用 KOSPI200 现货收盘冒充锚点，永续与现货的基差会被当成涨跌；HL 报价超 10 分钟未更新也暂停概率）；恒指收市后用恒指期货，锚点是**现货 16:10 收市那一刻**同一来源、同一合约月份的期货价：机器人在 16:10 一过就立即刷新期货（不等 60 秒周期），把收市后读到的第一笔（5 分钟内、当时新鲜的日市报价）存进 SQLite，重启不丢，16:10–16:30 日市、夜市和次日 09:15–09:30 的期货变动都相对它计算（例如 16:10 后期货涨 1%，估算就涨 1%，不再是“现价 ÷ 现价 = 0%”）。没记到这一笔（例如那段时间在重启）时，用同一合约 16:30 的日市收市价（夜市的“前收市”）作近似，明确标“近似”并且不给交易建议；16:10–16:30 之间连近似都没有时暂停概率。到期换月当晚夜市已是下月合约，与旧合约的锚点不混算。新浪 CFD 只和 CFD 自己的锚点对算。交易所盘中时直接用现货相对昨收：指数用各自的实时行情；合约在标的股票开盘后（上交所/港交所 09:30、韩交所 09:00，到收盘价确定后 15 分钟为止，周末和 `HOLIDAYS_*` 假日不算）不再用币安映射，改用股票自己的实时价（A 股/港股：腾讯 → 新浪，港股用腾讯 `r_hk` 实时接口；某个来源报价滞后时自动改用下一个；韩股：Naver，每 20 秒刷新），参考收盘仍是上一交易日收盘，代理一栏显示“上交所现货 78（腾讯·盘中直接用现货）”。开盘后还没拿到今日成交、全部来源失败或盘中超过 10 分钟没更新（午休不计）时，退回币安映射并在代理一栏写明原因（如“现货行情未取得……，暂用币安”）。
2. **σ 剩余** = 日波动率 × √(剩余交易分钟 / 全天交易分钟)。上交所 240 分钟、港交所 330 分钟、韩交所 390 分钟；收盘后到下个交易日开盘前按一整天计。日波动率 = 标的自己的交易所日 K（个股：A 股/港股腾讯前复权日 K → 东方财富，韩股 Yahoo `.KS` → Naver，近 30 个交易日；指数用 40 个指数日 K）的收盘对收盘对数收益标准差，与先验值（A 股 3.5%、港股 3%、韩股 3%、恒指 1.3%、KOSPI 2%）按 10 个样本的权重合成；不再用币安 24 小时日 K（它把夜间和周末也算进去，和按交易分钟缩放的口径不一致）。日 K 带开盘价时，个股和指数一样把方差拆成开盘跳空和开盘→收盘两部分：盘中直接用现货时只用开盘→收盘那部分。交易所日 K 取不到时用先验，并在 σ 说明里写出原因，10 分钟后重试。`PROB_VOL=UNITREEUSDT=3.5,HSI=1.2,KOSPI=2` 可手动指定。
3. **概率**：P(严格涨) = 1 − Φ(ln((参考 + 半个最小跳动) / 有效价) / σ)，P(严格跌) 同理，剩下的是平盘；公平价按平盘两边各得一半计算。最小跳动按交易所规则（A 股 0.01 元、港股价位表、韩股价位表、指数 0.01）。

限制：假期表只覆盖预设和手动配置的日期；代理（币安合约、HL KR200、恒指期货）与结算标的之间有基差，KR200 追踪的是 KOSPI 200 而不是 KOSPI 综合指数；σ 是历史估计，不同估法会让概率差十几个百分点；预测市场若对平盘另有规则，需要自行调整。`PROBABILITY=off` 关闭。

### 行情时效

旧行情不再产生新概率。每条行情分开记录“抓取时间”和“市场报价时间”：数据源没给报价时间（东方财富缺 `f86`、Naver 缺 `localTradedAt`）就记为未知，不再填成当前时间。etnet 页面正文不印时间：已收市的那一段按该段收市时间计；正在交易的那一段按“这组数字最早一次出现”的时间计，页面停住不变就会变旧，而不是每次都算“刚刚”。

统一规则（KOSPI、KOSPI200、上证、恒指现货与期货、A50）：

- 市场交易时段内，报价必须在 10 分钟内更新过（午休不计）；休市时，报价必须来自最近一个交易时段（收市前最后一小时的稀疏成交也算）；报价时间未知一律不算新鲜。
- 多个来源时，前面的源返回旧报价或没有报价时间，不算“取到了”，继续问下一个源；都不新鲜时保留最新的一笔用于显示，行末写明每个源停在哪里，后台状态记为失败。
- 交易所开盘期间现货报价失效（例如 KOSPI 的 Naver 报价停在 09:30、恒指页面还是昨天的、上证实时停更），暂停该指数的概率和优势建议；不会再拿停住的价格配上越来越小的剩余 σ 算出接近 100% 的结果。恒指现货另外核对“前收”是否等于上一交易日的日 K 收盘，对不上说明页面是别的日子的；开盘后还没变动过的现货（停在 09:30 之前）也不用。
- 日 K 收盘：多个来源按日期合并，落后的回复不会删掉已经确认的收盘，同一天优先保留排名靠前的来源（KOSPI：Yahoo ^KS11 优先于 Naver，恒指：腾讯 → 东方财富 → Yahoo）。个股交易所收盘：前一个源的日期比交易日历应有的更旧时继续问下一个源、取最新的；已保存的收盘不会被更旧的回复覆盖，并在状态里写明“收盘只取到 MM-DD”。
- HL KR200 的 15:30 锚点只接受**恰好**在 15:30（北京 14:30）结束的那一根 1 分钟 K（核对开始和结束时间）；缺这一分钟就退到同一时刻结束的 5 分钟 K，不会拿 14:26 开始的那根冒充。
- 先触价市场：币安现货价格超过 5 分钟没更新时暂停概率；开盘以来的路径还没核验、核验停在 3 小时前、σ 超过一天没更新，或有一分钟同时碰到两条线（先后不明）时，只显示盘口和优势，不高亮建议。市值阶梯：DexScreener 价格超过 5 分钟没更新时暂停概率与建议（已触及的档位仍算已触及）。价格阶梯：币安价格超过 5 分钟没更新时暂停概率（已触及的档位仍算已触及）；本月最高/最低核验停在 15 分钟以前或 σ 超过一天没更新时不给建议。

### 汇率与颜色

汇率每 6 小时刷新一次，来源为免费无需密钥的 Frankfurter（欧洲央行参考汇率，`api.frankfurter.app`），失败时改用 `open.er-api.com`；`/status` 底部显示汇率来源和日期。环境变量 `FX_RATES=CNY=7.12,HKD=7.79,KRW=1390`（每 1 美元兑多少该货币）可手动指定并优先于自动汇率。

`/status` 和涨跌提醒使用 HTML 加粗关键数字，并用颜色圆点标记涨跌：默认 `COLOR_STYLE=cn`（🔴 涨 🟢 跌 ⚪ 平，A 股习惯），设 `COLOR_STYLE=us` 则为 🟢 涨 🔴 跌。

### 状态卡片的版式

每个合约是一个树形小块，第一行是币安现价（成交稀疏时标注“标记价”）、币安指数价和行情时间，之后每行一个参照，格式统一为“来源 价格（时间·数据源）→ 币安现价相对它的偏差”：

```text
📍 宇树 UNITREE｜UNITREEUSDT
├ 币安 73.2｜指数 73.205｜09-23 15:53:05（9 秒前）
├ 基准 73.3（09-23 15:00 交易所收盘时刻·成交价）→ 🟢 -0.136%
├ 交易所 490.97 CNY ≈ 73.278（09-23 15:00 收·腾讯）→ 🟢 -0.11%｜当日 🔴 +0.36%
└ HL 73.279（24h 🔴 +0.03%·费率 0.0006%/h） → 🟢 -0.11%
```

基准行保留三位小数（触发判断用），其余两位。恒指期货和 KOSPI 放在卡片顶部，汇率放在页脚（`💱 1 USD = 6.7001 CNY · 7.79 HKD · 1,382.55 KRW｜Frankfurter 09-22`），数据源失败时只在对应行末尾追加一小段 ⚠️ 提示。涨跌提醒用同样的树形块，最后一行是触发原因。

### 手动记录与货币

价格后可以带货币代码（USD、USDT、HKD、CNY、CNH、KRW、JPY、TWD、EUR、GBP、SGD、INR），也可以写在首行作为整批默认。带非美元货币时按当前汇率折成美元再算“相对交易所”涨跌，没有该货币汇率时只展示数值；不带货币或 USD/USDT 时直接比较。`/setclose` 的手动参考价必须与币安合约同口径，不接受非美元货币。交易所收盘价只作对照，不参与阈值判断；触发仍以当前模式的基准（币安日 K 或手动参考价）为准。

省略日期时默认适用北京时间今天。也可以提前给次日设置；程序按适用日期分别保存，不覆盖今天的价格。

**价格必须和币安合约显示数值采用相同的计价口径。** 不要直接把韩国股票的韩元收盘数字与另一个币种的合约价格比较。币安界面的 USDT 后缀或美元显示也不能代替对具体合约计价规则、兑换方式、倍率的核验。本程序不会替你做这些换算。

手动参考价到该适用日北京时间 24:00 失效。下一天缺少新的参考价时，相关合约暂停涨跌提醒并提示缺失；不会把过期参考价一直当作“昨日收盘”。周末或假期需要继续使用同一个参考价，也必须明确设置对应适用日期。

切换回自动模式：

```text
/mode daily
```

## 日志与排错

### 数据源检测（/diag）

某个指标一直“暂缺”或数字对不上时，先发 `/diag`（或在服务器上运行 `python main.py --diag`，不需要 Token、不发消息）。它会把机器人用到的每一个数据源**单独**请求一次，而不是像平时那样一个失败就换下一个，所以能看出具体是哪一个源、哪一步出的问题：

```text
🩺 数据源检测 v1.12.2｜09-26 18:30:05（北京时间）
共 34 项｜✅ 30｜❌ 4
⚠️ 其余失败的源（同组有别的源顶上）：A50实时·东方财富、A50锚点·东方财富1分钟K 09-24 15:00 …

【A50实时】
❌ 东方财富（212 ms）：内容异常：东方财富返回的代码不是 A50 合约（XX00Y）｜f57=XX00Y f58=… f86=09-26 05:14
✅ 东方财富K线（180 ms）：14,196.5｜09-26 05:15（休市）
❌ 新浪CFD（3012 ms）：请求失败：网络错误 (URLError: timed out)
【A50锚点】
❌ 东方财富1分钟K 09-24 15:00（190 ms）：没有 2026-09-24 15:00 这一根（返回 0 根：无数据）
✅ 东方财富5分钟K 09-24 15:00（201 ms）：09-24 15:00 收 14,180（返回 2 根：…）
```

- 覆盖：币安（服务器时间、合约价）、每个合约的交易所收盘（每个源分别测）、上证实时/日 K、A50 实时（东方财富报价、东方财富 K 线、新浪 CFD）、A50 在上证收盘 15:00 的 1 分钟/5 分钟 K、恒指期货/现货、KOSPI/KOSPI200、Hyperliquid、汇率。每项单独限时 12 秒，同时最多 4 个请求。
- **请求失败**＝连不上（后面带真实原因，如 `Name or service not known` 是 DNS、`Tunnel connection failed: 403` 是出网代理拦截、`HTTP 403/451` 是对方拒绝）；**内容异常**＝连上了但返回的不是预期数据，后面附上返回内容的开头，方便看出是被拦截页、代码不对还是格式变了。A50 东方财富还会列出 `f57`（合约代码）、`f58`（名称）、`f86`（行情时间）原值。
- “🚨 整组全部失败”表示该数据当前完全拿不到；“所有数据源都失败”基本就是部署环境本身连不上外网。
- 报告最后是机器人当前的内部状态：每个后台刷新任务的上一轮结果——✅ 成功（各部分都拿到了有效的新数据）、⚠️ 部分成功（写明哪部分没取到）、❌ 失败（写明上次成功是多久以前）；没到刷新时间的空转不算一轮。只有拿到有效新数据才更新“成功时间”：例如恒指所有来源都失败或只返回旧报价时显示 ❌，不会再显示“✅ 0 秒前成功”。另外列出正在使用的上证收盘、A50 报价与锚点、上证概率或暂缺原因、恒指期货、各合约的错误和个股 σ 的来源。

**部署报 Token 错误：** 检查变量名和完整 Token，不要只填机器人的用户名。Token 不要包含额外引号或换行。

**`ADMIN_USER_ID 尚未配置`：** 先私聊机器人发送 `/id`，把返回的用户 ID 填入变量并重新部署。

**没有收到价格提醒：** 先发 `/subscribe`，再 `/status`。没有订阅、当前订阅暂停、价格没有严格超过阈值、冷却期内、基准或行情无效，均不会发涨跌提醒。

**`HTTP 409`：** 同一 Token 在多个地方运行或仍有旧实例。停止其他实例；副本数设为 1。不要同时让本地程序和 Railway 用同一个 Token 轮询。

**已有 Webhook：** 本程序不会擅自删除原服务的 Webhook。改用专用机器人，或者先在原服务中移除 Webhook 再启动。

**`HTTP 451/403`：** 服务地区、权限或访问规则不允许该请求。核对各平台官方规则、可用服务地区和部署配置。程序不会自动尝试绕过限制。

**`HTTP 429/418`：** 限流或临时封禁。程序会按返回等待时间暂停币安请求，避免继续高频请求。

**合约不存在：** 查看 `SYMBOLS` 和 `/status` 的错误。程序不会把 `HK0625USDT` 猜成其他股票或交易对。

**“最新成交价已过期”：** 接口里最新一笔成交的时间戳超过 120 秒，不把它当作即时价格。低成交活跃度也可能触发这种保护，不一定说明连接中断。

**重启后丢订阅：** 检查 Volume 是否挂在当前服务的 `/data`，以及 `STATE_DB` 是否为 `/data/bot.sqlite3`。

**构建成功但没有网站：** 正常，这是后台 worker，不提供网页，不需要添加域名。

每分钟日志会打印：

```text
heartbeat: valid_quotes=4/4 active_subscriptions=1 mode=binance_daily
```

日志中的 valid_quotes 是最近完成采样时的有效项计数，不等同于持续健康保证。以 `/status` 中的行情时间和基准日期一起核对。

## 本地测试与行情诊断

Python 3.12 环境下运行离线测试，无须 Token，无须联网：

```bash
python tests/run_all.py            # 全部 42 组
python tests/run_all.py sse exmode # 只跑指定几组
```

每组测试开头都会导入 `tests/offline.py`，任何真实 HTTP 请求都会立即失败，结果不受网络影响。`test_web.py` 在装有 Playwright + Chromium 时还会用无头浏览器渲染网页，否则跳过这一步（Docker 构建里就是跳过）。

只测试真实币安接口，不推送 Telegram：

```bash
python main.py --check
python main.py --diag   # 检测全部数据源，任一失败时退出码为 1
```

`--check` 固定诊断自动日 K 模式，逐个输出最新价、上一完整日 K、偏离值；失败返回非零退出码。当前生成环境无法联网完成此真实接口测试，见 `TESTING.md`。

本地启动机器人时要把配置写入操作系统环境变量；本项目不会自动读取 `.env` 文件。使用 Docker 时可以让 Docker 读取自己保存的私有 `.env`：

```bash
docker build -t tg-close-alert-bot .
docker run --rm --env-file .env -v "$(pwd)/data:/data" tg-close-alert-bot
```

仅使用一个运行实例。本地测试真实 Bot 时应先停止 Railway 同 Token 的实例。
